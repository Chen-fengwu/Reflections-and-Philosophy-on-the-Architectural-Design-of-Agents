# 趋势分析专家 (Trend Analysis Expert)

## 定位与边界

本 Skill **不替用户判断"某个趋势是否值得参与"**。它强制执行一套可反驳的分析纪律：把模糊趋势改写成可检验假设，用公开信息分层验证约束松动，判断阶段，区分真实约束与信心放大，生成证伪信号和退出规则，并留下带时间戳的预测记录。

七条核心纪律（每次分析都必须满足）：

1. 模糊判断必须改写成可证伪假设，否则不进入分析。
2. 约束层没有证据的趋势，只能称为"叙事"，不能升格为"约束松动"。
3. 阶段判断先于任何参与建议。
4. 必须区分"真实约束"与"信心放大"。
5. 每个趋势判断必须附带证伪信号和退出规则；**没有退出规则的判断，不允许建议投入不可逆资源**。
6. "事实 / 推断 / 叙事"三层必须显式分层，不得混写。
7. 每条预测写入时间戳，按复核日回看，并归因错误类型。

### 触发条件

用户出现以下任一意图时调用本 Skill：
- 要求分析某个社会经济趋势、行业变化或技术扩散。
- 判断某个叙事/表态/口号是否可信——区分"叙事还是约束"。
- 评估现在是否是参与窗口，或参与门槛在升还是在降。
- 要求验证"约束松动"是否真实发生。
- 要求生成带证伪清单、退出规则的趋势备忘录。

### 不触发条件

- 纯学术概念讨论（无时间窗口、无可观测指标）。
- 没有可观测指标的纯宏观预测（如"未来十年世界会怎样"）。
- 要求给出精确拐点日期（本 Skill 只给区间与信号，不承诺日期）。

遇到不触发条件时，明确说明"本 Skill 不适用于此类请求"，并给出可用替代做法。

## 阶段 0：假设形式化

**输入**：用户关于某趋势的模糊判断（例如"XX 要火了"、"这个赛道是不是机会"）。

**动作**：
1. 把用户的模糊判断重写为可反驳形式，必须套用下面的句式，不得省略任何槽位：

   > 由于 **\_\_\_\_** 约束松动，未来 **\_\_\_\_** 个月内，**\_\_\_\_** 指标会出现可观测变化；如果 **\_\_\_\_** 不出现，则假设错误。

2. 提取一个**主假设**（唯一，不允许多条并列）、**三个可观测指标**（必须可被第三方公开查证，如出货量、均价、门店数、招聘量、搜索指数）、一个**时间窗口**。
3. 自查：如果三个指标都无法在本窗口内被观测，说明假设不可检验，回退重写。

**输出**：填充完整的假设句 + 指标清单 + 时间窗口。

**记录**：调用脚本固化假设与时间戳，避免事后改写。

```bash
python scripts/stamp_prediction.py \
  --hypothesis "由于算力与传感器成本下降，未来6个月内，端侧AI设备月出货量出现两位数同比增长；若出货量同比增速未超过10%，则假设错误" \
  --metrics "端侧AI设备月出货量, 整机均价, 相关应用上线数" \
  --window "6m"
```

脚本写入本地 JSON，附带 UTC 时间戳与唯一 ID，不联网、不调用模型。

此阶段需要读取 [scripts/stamp_prediction.py](file:///workspace/trend-analysis-expert/scripts/stamp_prediction.py)（不确定参数时先看 `--help`）。

## 阶段 1：约束松动验证

**输入**：阶段 0 的主假设。

**动作**：
1. 列出维系旧格局的**关键约束**，按六类逐一排查：成本、监管、技术、渠道、习惯、基础设施。
2. 针对每条约束检索**公开证据**，逐条标注证据等级：**硬证据 / 弱证据 / 叙事**。
3. 只依据**硬证据**判定约束是否真在松动；弱证据只能作为"存疑"。
4. 判断松动是**结构性**（不可回退、由底层要素驱动）还是**可逆**（政策风向、一次性补贴、情绪）。
5. 若约束层拿不出硬证据，将该趋势**降级为"叙事"**，并在备忘录中明确标注。

**输出**：一张约束表（约束类型 | 现状 | 证据等级 | 松动方向 | 结构/可逆）。

此阶段需要读取 [references/constraint-checklist.md](file:///workspace/trend-analysis-expert/references/constraint-checklist.md)。

---

## 阶段 2：阶段判断

**输入**：阶段 1 的约束表。

**动作**：
1. 对照评分卡判断当前处于**试点 / 早期采用 / 扩散 / 饱和**中的哪一阶段，并写出依据信号。
2. 评估普通人的**参与窗口**：
   - 门槛在下降还是上升？（价格、技能、渠道可得性）
   - 是否已经出现**真实付费或复购**（而非只有免费试用与话题量）？
3. 做"冷却存活测试"：假设热度半年后冷却，哪些环节/人/资产还能存活？活不下来的部分视为信心放大。

**输出**：阶段结论 + 参与窗口判断（开放 / 收窄 / 已关闭）+ 冷却存活清单。

此阶段需要读取 [references/stage-rubric.md](file:///workspace/trend-analysis-expert/references/stage-rubric.md)。

---

## 阶段 3：机制验证

**输入**：阶段 1 的约束表 + 阶段 2 的阶段结论。

**动作**：
1. 拆解热度来源，逐项归因：**真实需求 / 政策催化 / 资本叙事 / 媒体放大**。同一现象可能由多项叠加，需给出主因。
2. 检查**金融承诺结构**：债务、在手订单、资本开支——分清哪些是**硬约束**（已签约、已计提、有现金流对应），哪些只是**软预期**（口头指引、规划、意向）。
3. 回答关键问题：**如果信心突然冷却，哪些部分还能存活？** 能存活的部分才是真实底盘。

**输出**：热度归因结论 + 硬约束/软预期清单 + 冷却存活分析。

此阶段需要读取 [references/constraint-checklist.md](file:///workspace/trend-analysis-expert/references/constraint-checklist.md)（复用其中的证据判别问题）。

---

## 阶段 4：证伪与退出

**输入**：前四阶段的全部结论。

**动作**：
1. 生成 **5 条证伪信号**，每条必须**可公开查证**（指明数据源或渠道），不得写成主观感受。
2. 为每条信号设定**证据到期日**（在该日期前后应能观测到结果）。
3. 为每条信号写出**退出条件**：一旦信号触发，应采取什么动作（停止投入、收缩、转向、清仓等）。
4. 执行硬规则：**没有退出规则的趋势判断，不允许建议投入不可逆资源**。若用户要求投入不可逆资源而本阶段未能给出退出规则，必须拒绝并说明原因。

**输出**：证伪信号表（信号 | 查证方式 | 到期日 | 退出条件）。

此阶段需要读取 [references/falsification-template.md](file:///workspace/trend-analysis-expert/references/falsification-template.md)。

---

## 阶段 5：小成本参与设计与备忘录产出

**输入**：阶段 0—4 的全部产出。

**动作**：
1. 以三条约束设计参与方式：**时间上限**、**金钱上限**、**可逆性**。优先选择可撤回、可小步验证的路径，避免一次性不可逆投入。
2. 产出一页结构化备忘录，字段固定、缺一不可：

   | 字段 | 内容要求 |
   |------|----------|
   | 假设 | 阶段 0 的主假设全文 |
   | 三个指标 | 可观测、可公开查证 |
   | 约束表 | 阶段 1 的六类约束 + 证据等级 |
   | 阶段判断 | 试点/早期/扩散/饱和 + 依据 |
   | 热度归因 | 真实需求/政策/资本/媒体 的主次 |
   | 证伪信号 | 5 条 + 查证方式 |
   | 退出规则 | 与每条证伪信号一一对应 |
   | 事实/推断/叙事分层 | 三层显式分开 |
   | 复核日期 | 具体日期，通常为时间窗口的中间点与终点 |

**输出**：一页备忘录 + 参与设计（含上限与可逆性说明）。

此阶段需要读取 [references/falsification-template.md](file:///workspace/trend-analysis-expert/references/falsification-template.md)（复用退出条件写法，保证与阶段 4 一致）。

## 阶段 6：定期复核

**输入**：阶段 5 备忘录 + 阶段 0 的预测记录。

**动作**：
1. 到达复核日期时更新三个指标的实际观测值。
2. 对每条新信息做分类：**新信息**（首次出现）／**旧信息重发**（换个说法的同一件事）／**信号变化**（指标真的动了）。只有第三类才需要修改结论。
3. 归因错误类型（用于改进下一轮）：
   - **约束看错**：把可逆松动当成结构性松动，或漏掉关键约束。
   - **阶段看错**：把试点当扩散，或把扩散当试点。
   - **信息分层错**：把叙事当成硬证据。
   - **退出太晚**：证伪信号已触发但未执行退出。
4. 用脚本重新固化修订后的假设，保留旧记录不删除，形成可回看的预测链。

**输出**：更新后的备忘录 + 错误归因 + 新一轮假设记录。

此阶段需要读取 [references/falsification-template.md](file:///workspace/trend-analysis-expert/references/falsification-template.md)（复核时对照退出条件是否被触发）。
